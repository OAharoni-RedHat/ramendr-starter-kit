RamenDR hub ↔ managed connectivity

Three install variants: odf (MCG S3 on managed clusters; Submariner required), drpartner-s4 (hub S4 + array-native replication; Submariner disabled), and drpartner-minimal (ACM + partner operators only; no S4 or Submariner).

drpartner-s4 connectivity map

ACM needs DNS resolvability of managed cluster APIs. S3 metadata lives on hub S4. Volume DR is array-native (VSA ↔ VSA). Submariner is not deployed (submariner.enabled: false in opp-policy).
ACM + DNS Hub S4 Storage / VSA

drpartner-s4: Hub S4 detail

odf connectivity map

ACM needs DNS resolvability of managed cluster APIs. S3 metadata buckets (MCG) live on each managed cluster — hub and peers both reach those endpoints. Submariner is required for ODF RBD cross-site replication.
ACM + DNS Managed MCG S3 Submariner (required) ODF volumes

odf: Managed MCG S3 detail

drpartner-minimal connectivity map

ACM needs DNS resolvability of managed cluster APIs. Deploys partner operators (MCO/Ramen, CNV, OADP) and Hive/BYOC plumbing only — no vp-s4-storage, no DRClusters, and no Submariner. Volume DR is external to the pattern.
ACM + DNS External VSA (dashed)

Shared requirements

  • ACM + DNS — Hub must resolve each managed cluster API hostname, then connect over HTTPS 443 / kube API 6443.
  • TLS / CA trust — Trust custom certs for S4 (s4 path) or MCG endpoints (odf path).
